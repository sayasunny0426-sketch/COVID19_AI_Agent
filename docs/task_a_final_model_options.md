# 最終 CXR モデルの構成：単一 seed か 3 seed ensemble か（推奨案）

- 作成日：2026-09-21　状態：**推奨案。未承認。Test 評価は未実施**
- 前提：学習条件は `lr3e-4_aug_b` に確定（D-055）。seed 42 / 43 / 44 の 3 run が既に存在し、各 run の best checkpoint と Validation 予測は保存済み

---

## 1. 論点の整理

| 観点 | 単一 seed | 3 seed ensemble（予測確率の平均） |
|---|---|---|
| 研究目的（CXR / 臨床 / マルチモーダルの比較） | CXR model の性能が seed の偶然に左右される。今回の SD は 0.0046 と小さいが、Test の死亡 17 例では偶然の影響が相対的に大きい | seed による揺らぎを平均化し、「この条件の CXR model」の性能をより代表する |
| どの seed を使うかの決め方 | Val で最良の seed を選ぶと、**Val（死亡 17 例）での選択**が 1 段階増え、楽観的になる。事前指定（seed 42）なら選択は増えないが、他の 2 run を捨てる | 選択が不要。3 run をすべて使う |
| Task C（Late Fusion）への接続 | 患者ごとに 1 つの確率が出る。単純 | Late Fusion は decision level の統合なので、平均確率をそのまま使える。**実装上の追加負担はない** |
| 再現性 | checkpoint 1 個。最も単純 | checkpoint 3 個（合計約 134 MB）。seed と構成を記録すれば完全に再現可能 |
| 公平な比較 | 他モデル（LR、XGBoost）は seed による揺らぎが小さい／ない | **注意点**：CXR だけ ensemble にすると、Task B の MLP など他の確率的モデルとの扱いが非対称になる |
| 課題要件 [T] | 「ResNet18 を使用する」を満たす | 同一条件・同一アーキテクチャの 3 個の平均であり、ResNet18 の枠内。ただし**報告時に ensemble であることを明示する必要がある** |

---

## 2. 推奨案

### 主解析：**3 seed ensemble（予測確率の単純平均）**

**理由**
1. **偶然の影響を小さくする**：Test の死亡は 17 例で、AUROC は数例の順位変動で大きく動く。学習の乱数で決まる部分を平均化しておくことは、モデル比較を目的とする本研究の趣旨に合う。
2. **Val での選択を増やさない**：単一 seed を選ぶには「どの seed か」を決める必要がある。Val で最良の seed を選べば、死亡 17 例に対する選択が 1 段階増えて楽観的になる。ensemble なら選択は不要で、条件選択（既に完了）以上に Val を使わない。
3. **Task C に無理なく接続できる**：主解析の Fusion は Late Fusion（decision level）なので、平均確率をそのまま使える。
4. **既存 run をそのまま利用できる**：追加学習は不要。

### 副次（必ず併記）：**各 seed 単独の結果**

各 seed の患者単位予測と性能を Test でも算出し、`test_predictions_seed42/43/44.csv` として ensemble とは別ファイルに保存する（D-045 で既に決定済み）。これにより、
- ensemble の利得がどの程度か
- seed 間で結論（CXR vs 臨床 vs マルチモーダルの大小関係）が変わらないか
を確認できる。**主解析は ensemble であると事前に宣言**し、seed 単独は感度分析として扱う。

---

## 3. 公平な比較のために同時に決めるべきこと（重要）

**確率的なモデルはすべて同じ規則にする**、という原則を提案する。

| モデル | 乱数の影響 | 提案する扱い |
|---|---|---|
| CXR（ResNet18） | あり | **3 seed ensemble**（主）＋ seed 単独（副） |
| Task B: MLP | あり | **同じく 3 seed ensemble**（主）＋ seed 単独（副） |
| Task B: XGBoost | 小（サブサンプリング等） | 単一 seed（42）で固定。ensemble にしない |
| Task B: Logistic Regression | なし（決定的） | 単一モデル |
| Task C: Late Fusion | 上記の出力を統合 | 主解析は ensemble 同士を統合 |

この扱いにすると、「乱数の影響があるモデルには同じ変動抑制を適用する」という一貫した基準になり、CXR だけが有利になる状況を避けられる。**この規則は Test 評価の前に固定する必要がある。**

---

## 4. 単一 seed を選ぶ場合（採らない場合の条件）

もし単純さを優先する場合は、次を守る必要がある。
- **seed 42 を事前指定**する（Val で最良の seed を選ばない）
- 3 seed の Val 性能のばらつきを limitation として報告する
- Task B の MLP も同様に seed 42 固定にする

---

## 5. 決めていただきたいこと

1. 主解析を **3 seed ensemble** とするか、**単一 seed（42 固定）** とするか
2. §3 の「確率的モデルは同じ扱いにする」原則を採用するか（Task B の MLP の扱いに影響する）
3. 決定後、`final_selection.json` に構成・checkpoint の hash・閾値の決め方を凍結してから Test 評価に進む
